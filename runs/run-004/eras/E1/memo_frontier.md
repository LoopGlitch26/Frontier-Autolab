# Frontier Research memo — E1

**Yuki Harada:** Build for the installed base. The near-term frontier is not a new network; it is making existing LANs diagnosable. Proposal A: collect authorized configuration snapshots and technician-confirmed fixes for one NetWare environment. Proposal B: test a private linked information library for one research group. The CERN proposal is a signal to watch, not proof of a market.

**Samuel Brandt:** Cross-system support is an old source of friction. A compatibility guide decays quickly, so repeated incidents and a measured baseline matter more than a large static database.

**Ines Varga:** Three paths: LAN administration becomes a durable support job (base); vendors bundle diagnostics (downside); linked internal documents create new information workflows (upside, low confidence). Watch repeat incident rates, support hours, and willingness to pay.

**Kofi Mensah:** Missing measurement is operational: which configuration caused an incident, what fix worked, and whether a repeat was resolved faster? Do not automate collection before users consent and technicians record cases consistently.

**Recommendation:** Pilot a diagnostic casebook for one authorized NetWare installation. Measure incident resolution time, recurrence, and support effort. Keep the linked-library idea as a small discovery interview, not a build commitment.
