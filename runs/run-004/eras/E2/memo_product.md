# Product & Engineering memo — E2 · January 1996

**Priya Nair:** The pilot favors deepening one support setup rather than expanding across systems. A technician-side guided diagnostic can work offline and reuse installed-software workflows.

**Jonah Reyes:** A technician may use the tool while a service manager pays. Confirm the budget owner and baseline before building.

**Hana Kowalski:** A shared departmental incident database offers management visibility but adds concurrency, backup, and LAN support costs. Keep the first release local and exportable.

**Leo Mbeki:** Do not assume public Internet connectivity is the product's runtime. Make records portable; add integrations only when customers request them.

## Proposals

1. **Technician troubleshooting assistant:** a local PC tool for one supported configuration, with guided checks, incident capture, and lookup of verified resolutions. The next capability is safe guidance from recurring cases. Risk: inconsistent records and unproven payer. No automated diagnosis in the first release.
2. **Departmental incident tracker:** a shared queue for one support department over one tested LAN, with printable reports and export. The next capability is recurrence and workload reporting. Risk: adoption, data recovery, and customer-specific network support.

Priya favors an offline tool; Hana sees expansion in shared records; Jonah requires proof of buyer and workflow; Leo supports portable data. **Playbook application:** use one configuration and measure baseline/support burden. The departmental tracker waits for proof that staff keep its records current.
