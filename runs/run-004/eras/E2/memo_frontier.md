# Frontier Research memo — E2 · January 1996

**Dr. Yuki Harada:** Windows 95 shipped last year, adding another PC environment. That may create support demand, but complexity alone does not prove willingness to pay. Keep the pilot narrow and ask who owns the budget.

**Samuel Brandt:** The Web moved from proposal to publicly available software after CERN's 1993 release and NCSA Mosaic. That makes linked information a more concrete experiment, not proof of an enterprise market.

**Ines Varga:** Desktop change and browser-based information access are both possible sources of new work. A small company should test each against a named payer and recurring workflow before choosing.

**Dr. Kofi Mensah:** Preserve compact workflow logs. Measure case frequency, resolution time, repeat incidents, and technician intervention against a baseline.

## Proposals

1. **Repeatable troubleshooting for one PC/LAN configuration.** Extend the pilot only if a support manager owns the problem and agrees to a success measure. Keep logs of symptoms, configuration, steps, time, and verified outcome. Later guide technicians through proven steps. Kill if the problem is rare, cheap, or too costly to support.
2. **Internal Web publishing for one research group.** Validate a content owner and maintenance workflow before building a general tool. Measure preparation time, link maintenance, retrieval tasks, and successful finds. Later improve retrieval from observed use. Kill if content work dominates or the project becomes bespoke.

Harada and Mensah favor deepening the troubleshooting pilot; Varga asks for a small publishing workflow study. Brandt cautions that Web availability is only a signal. **Playbook application:** validate the payer and workflow first, and keep one supported configuration while measuring support burden.
