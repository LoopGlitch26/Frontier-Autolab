# E3 board decision — 1 January 2002

The company has not established willingness to pay for the diagnostic workbench. The Red Team rightly warns that the new e-commerce proposal introduces integration and exception-authority risks, while the existing workflow risks becoming services. The executives agree that the company should pivot only to a manual trial that tests a new, budget-bearing workflow without building connectors.

## Decision

**Company:** Switchyard Commerce Operations — manual exception triage for one online merchant's order workflow.

**Thesis:** Online orders create operational records across order, fulfillment, and payment steps. If discrepancies recur, the adoption bottleneck is not generic connectivity but deciding who should act on a specific exception. Begin with manual triage for one merchant; own a structured exception record and verified resolution data; automate prioritization only after consistent cases, authorized access, and a paid pilot.

**Wedge:** One online merchant with a named operations owner; manually review at least 50 authorized historical discrepancies. No live integrations. This is an experiment, not a claim that merchants have a software budget.

**Three-year plan:** Secure case access and paid-pilot commitment; test prioritization and resolution-time gates; build only a narrow import tool if records are stable; validate a second buyer with under 20% bespoke implementation before scaling. Keep the existing support workflow only as a learning asset, not an active product line.

**Kill criteria:** Apply Red Team gates; no paid pilot, insufficient/unauthorized case data, poor prioritization, no faster next action, or highly variable rules means stop. Capital remains constrained; no marketplace or broad integration platform.

**Kill / keep:** Kill the PC/LAN assistant build and general procedure editor. Keep the manual measurement discipline, portable records, and support-case rigor. The company name changes to reflect the tested workflow, not a validated market.

**Dissent:** CTO favors keeping the troubleshooting tool in maintenance; GTM argues for a parallel provider pilot. CEO chooses one experiment to avoid splitting scarce capital. This is an intentional pivot based on testability, not evidence that commerce is already a better market.
